# Fourge regression suites

Everything the engine's releases are checked against, in one place that survives any one machine.
They run on every pull request that touches `admin/`, `fleet-dashboard/` or `tests/`
(GitHub Actions workflow *Regression suites*) and locally with one command.

```
cd tests && npm test          # or: bash tests/run.sh from anywhere
```

Needs node 18+, php 8+ with `pdo_sqlite`, `curl`, `python3`, and a Chromium. The harness looks for
`CHROME_PATH`, then a Playwright browsers folder (`PLAYWRIGHT_BROWSERS_PATH` or `~/.cache/ms-playwright`,
which `npx playwright install chromium` fills), then a system Chrome. `npm test` installs `playwright-core`
on first run; the CodeMirror files the admin loads from cdnjs are cached once under `tests/.cache/cm` so the
browser suites never depend on the CDN.

## What runs

`run.sh` serves the repo root with `php -S` on port 8931 (reusing a server that already answers there;
`TEST_PORT` / `TURL` override it) and then runs:

| Step | What | Where |
|---|---|---|
| Browser suites | Headless Chromium drives the **real** `admin/index.html`; `apiCall`, `toast` and `ghMirror` are stubbed with an in-memory file store, `data/*.json` answered inline, third-party requests aborted | `browser/*.mjs` |
| PHP suites | Functions lifted out of `admin/api.php` by name and run on their own (no dispatcher, no server): the managed browser-caching block (`htaccess_cache.php`) the GitHub client — failure explanations, `[skip ci]`, the mirroring writer `fourgeSitePut` (`gh_client.php`), and the canonical-host redirect block with its notion of a non-production host (`htaccess_canonical.php`) | `api/*.php` |
| Dispatcher end to end | A throwaway copy of the site with its own `config.secret.php` and SQLite DB, served by `php -S` on port 8932 with `display_errors` on; a real login, one request per action, every response must be valid JSON, and the server log must stay free of PHP notices GitHub is a stub `php -S` on port 8934 (`lib/gh_stub.php`: `/user` with the token-expiry header, the repo, the Git Data API and the Contents API; modes `ok` / `401` / `ratelimit` / `notfound`, every request logged), reached through `FOURGE_GH_API_BASE`, so the one-commit sync, `[skip ci]`, fail-fast on a rejected token and the server-side writers' mirroring are proven request by request. GoHighLevel is a second stub on port 8935 (`lib/ghl_stub.php`: contacts, conversations, inbound messages and Conversation AI agents, with a main Live Chat bot that answers on auto-pilot; switches for a Conversation AI API that only takes Version v3 and for a CRM that insists on a conversation provider id), reached through `FOURGE_GHL_API_BASE`, so Fourge Chat is proven end to end: the chat's on/off switch, the contact and conversation it opens, messages handed over as inbound Live Chat, a visitor seeing only chat messages from their own chat (not another channel, not a contact's history), the rate limits, creating / reusing / editing the bot without losing what the CRM holds, the AI test with provider-id discovery, and Super Admin-only bot access. A new password for the shared editor44i account (`fourgeManagedPasswords()`: a change id and a bcrypt hash) lands on the first sign-in: checked through the database, since the password itself is not in the repository, the account gets the hash, its forced change is cleared and its open sessions end, the seed for new sites matches, the old password is refused, and a password set later on the site is kept rather than put back. A copy of the Fleet Dashboard that came with the repository is removed by the sign-in self-heal, from the server and from the site's repository, while a set-up dashboard or a folder holding files of the site's own is kept, and the folder is never listed as a page. An editor with Analytics switched off gets none of its data (ga_status / ga_report / ga_save_credentials refused in the same session), and the Google credentials save and read back. Anthropic's Messages API is a third stub on port 8936 (`lib/anthropic_stub.php`: modes `ok` / `overloaded`, every request counted), reached through `FOURGE_ANTHROPIC_API_BASE`, so the hourly AI allowance is proven: 41 answers in an hour (the old limit was 40), an attempt Anthropic turns away not counted, and a site's own `ai_rate_per_hour` refusing the next request before it reaches Anthropic, saying when the hour resets. The site server runs with `opcache.revalidate_freq=0`, so an edit to its `config.secret.php` applies to the next request. The first sign-in writes an `llms.txt`. An SEO platform deploy package in the platform's current format (`ydg-deploy-package`) previews without writing and applies: a title tag, meta description and H1 run into the slug field are split out and used (the page's `<title>`, description and single H1; the post's excerpt), a sentence-long slug gets a short file name, `seo_title` / `seo_description` fields are used, the old format name is still accepted and any other file refused. The AI auto-fix runs (its preview asks the AI stand-in about a page with a weak title and writes nothing; a run saves its state) Form email is proven against a stand-in SMTP relay on port 8937 (`lib/smtp_stub.php`: AUTH LOGIN, a 550 for any recipient starting "refused", every accepted message logged as a JSON line): a legacy `send.php`'s `cc_email` is copied on every form email (envelope and `Cc:` header; a commented-out line, a bad address and a refused CC left out), never to the address it is already addressed to, the mail test lists the CC and sends only to the address typed, and `config.secret.php`'s `mg_notify_cc` wins. A form email goes only to the site's own addresses: a request naming an outside address (alone, mixed with the site's own, or in a multipart post) is sent to Site Info's Notify Email instead and the outside address appears nowhere in the relay log, the mail settings' recipient is used as given, and an empty "to" stores the entry without emailing. Captcha secret keys never stay in the public `data/site.json`: a write carrying one moves it to the encrypted secret store (a newly saved one replaces the stored one, a write without one keeps it, and forms are still checked with it), and the sign-in self-heal moves a copy still in the file without letting an old copy replace the stored secret. Scheduled package content that comes due is released: a page's Fourge noindex stamp becomes index and the page, or the post, joins `sitemap.xml` once; a page that went live before this fix is repaired the same way, and one marked noindex in SEO stays out | `api/e2e_dispatcher.sh`, `lib/gh_stub.php`, `lib/ghl_stub.php`, `lib/anthropic_stub.php`, `lib/smtp_stub.php` |
| Static checks | `php -l admin/api.php`; every inline `<script>` in the admin parses; no direct `curl_close()`; every top-level `define()` / `const` in `admin/api.php` sits above the request dispatcher (one below it never exists while the dispatcher runs: "Undefined constant" on PHP 8); `version.json` = `CMS_VERSION` = `FOURGE_API_VERSION` | `run.sh` |

## Writing a suite

Import the harness and drive the real functions:

```js
import { openAdmin } from '../lib/harness.mjs';
const { p, chk, done } = await openAdmin();          // page, assertion helper, finisher
await p.evaluate(() => { _site = { name: 'T' }; });   // the admin's own globals (lexical bindings: assign them bare, not window._site)
chk(await p.evaluate(() => typeof someAdminFunction === 'function'), 'the function exists');
await done('my suite');                               // prints the summary and sets the exit code
```

`openAdmin()` reveals the signed-in shell (needed for layout-dependent clicks), stubs `apiCall` with
`window.__files` (read_file / write_file / list_pages via `window.__pagesList`), logs writes to `window.__writes`
and toasts to `window.__toasts`. `launchPage()` gives just the page for suites that stub the API themselves.
Pages the visual editor should open are best served through the normal flow: put the page in `window.__pagesList`,
answer its URL with `p.route(...)`, call `goPanel('p-pages')` and wait for the bridge (`#__fe_ov__` in the iframe).

## Notes

- `tests/` is excluded from the FTP deploy (`.github/workflows/deploy.yml`) and is never part of an engine update
  (the updater installs only the `files` manifest in `admin/version.json`).
- `tests/.cache/` (CodeMirror cache, server logs, the dispatcher's throwaway site) and `tests/node_modules/` are git-ignored.
- The PHP built-in server is single-threaded and stalls on Chromium's speculative preconnections; `run.sh`
  starts it with `PHP_CLI_SERVER_WORKERS=4`. Headless Chromium also never finishes a real request to a second
  local origin, which is why `element_css.mjs` answers its cross-origin stylesheet by request interception.
